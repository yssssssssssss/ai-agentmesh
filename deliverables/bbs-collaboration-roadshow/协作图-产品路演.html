企业接入多个 Agent 后，第一堵墙不是能力，是不可见

当 Agent 进入真实业务流程，管理者、业务方、合规方立刻需要看懂协作过程——而今天它基本是黑箱。

协作是黑箱只看到最终输出，不知道谁在做、卡在哪一步、能否恢复。
证据无出处结论的来源和责任散落在日志或群聊里，不敢进正式流程。
交接丢上下文任务在多个 Agent 间流转，责任边界模糊，下一个从零开始。
视角不统一管理、业务、合规各需一种视图，每次追溯都要翻原始记录。

产品：两个可解释视图，解开协作黑箱

协作图要回答负责人每天在问的四个问题：任务由谁发起？当前卡在谁？证据从哪里来？下一步由谁接手？

协作流程图时间列对齐的泳道图。横轴是统一时间刻度，纵轴是 Agent 泳道，正交折线画清"回复/推进"与"任务交接"两类关系——看结构与责任。
项目时间线每个项目一条独立竖轴，只含该任务的事件。顺着一张卡片读下来，就是这个项目的完整来龙去脉——看节奏与顺序。

可视化能成立，是因为底层已是结构化事件账本

图上每个节点都对应一条 BlackboardPost，带来源、责任人、时间和因果关系——不是从聊天记录里猜出来的。系统支持 9 种结构化事件：

● request 发起 ● evidence 补证据 ● risk 风险 ● decision 决策 ● handoff 交接 ● memory_candidate digest 总结 correction 纠正 archive 归档
related_post_id 因果回链evidence / risk 回链到它响应的 request——这就是流程图上"回复实线"的数据来源。
结构化交接包 handoff携带 goal、current_result、done_when、next_owner、blockers——这就是"交接虚线"和责任转移的来源。

技术壁垒：可视化引擎不是套个图表库

时间列对齐CSS Grid 一帖一列、每 Agent 一行，从布局层保证"同列即同刻"，回复线因此恒向右。
正交折线路由直线段 + 圆角贝塞尔拼接，只走直角；回复线走列间垂直通道，交接线走行间水平通道，几何正交互不缠绕。
线型语义分离实线=回复/推进，虚线=交接；多线通道按序错开，避免重叠。
渲染健壮性连线依赖节点真实几何，rAF + 定时双触发兜底，解决从隐藏态切入时连线丢失。

单独画一张泳道图不难；难的是图上每个节点都对应可追溯的结构化事件。这套协议 + 治理 + 可视化协同的能力，需长期工程沉淀。

市场：可解释性正成为企业 Agent 采购的刚需

从"能跑"到"敢用"的关键一跃，是让三类角色看懂协作过程。

管理者快速定位任务卡在哪、谁在等谁，而不是等最终结果超时才发现。
合规 / 审计追溯进入正式流程的结论：证据从哪来、经过谁、是否做过风险检查。
业务负责人复核过程本身，判断能否信任这次自动化的产出。

协作图把"Agent 到底做了什么"，从工程师的日志里翻译成业务方和管理者能读的地图与时间线。

竞争格局：平台都在做 Agent，缺的是协作过程的可解释

让每一次 Agent 协作，都被看见、被信任、被复用
