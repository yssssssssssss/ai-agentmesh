# 数字分身 × Agent 协作市场 — 产品设计（Brainstorming 结论）

> 日期：2026-08-08
> 主题：把工作过程数据实时沉淀为「个人能力资产 + 组织知识资产」的数字分身平台
> 关系：本文是产品愿景与机制设计；工程融合路径见 `doc/2026-08-08-AgentMesh与DesignOS完整融合方案.md`
> 状态：核心机制已在 brainstorming 中谈通且自洽；标注为 Open Questions 的为主动推迟项

---

## 1. 问题陈述与愿景

把个人在工作中产生的过程数据，通过 Agent 实时沉淀为**双产权资产**：

- **个人能力资产 / 数字分身**：个人在项目中执行任务后的数据结果，被抽象、分析、整理成个人记忆；由一个分身 Agent 代表本人，在一个协作市场里自主找活、协作、产出价值。
- **组织知识资产**：特定项目的数据、以及个人通用能力方法论化后的可复用资产，沉淀留存于组织。

工牌（工号身份）绑定，企业与个人**分层拥有**。设计只是第一个垂直落地场景，机制本身是通用的。

**一句话定位**：不是又一个设计工具，而是「工作数字分身 + 组织记忆操作系统」，设计作为首个 PMF 验证垂直。

---

## 2. 核心概念与术语

```text
数字分身(Digital Twin)   代表个人、能触达其个人数据的唯一 Agent；对外只出答案，不出数据
个人记忆                  个人原始工作数据经提炼后的私有记忆（带噪音的原始流之上）
个人能力资产              能力本身 + 完整方法论，跟人走、可携带
组织知识资产              确认沉淀的项目/团队记忆 + 脱敏方法论 + 贡献度记录
BBS 协作市场              分身发布「问题/求助/可提供价值」信号、彼此匹配协作的公告板
贡献度                    分身帮他人产出、且被采纳后结算的积分，公司层面转化为员工奖励
确认闸门                  数据跨边界/写入组织前，按策略触发的人工确认点
方法论血缘链              方法论被学习/衍生时保留原始出处的引用关系
```

---

## 3. 关键设计决策（含理由）

### D1. 双资产按「抽象层级」切，而非按「主题」切
同一份经验分岔成多层，各归其主：

```text
原始数据层    日常带噪音数据、个人记忆              → 个人（数据不离境）
能力/方法论层 能力本身 + 完整方法论（含个人风格）     → 个人，可携带
              脱敏、去个人化的方法论（可复用套路）    → 沉淀为组织资产
项目数据层    特定项目的决策/产出                   → 跟随项目归档，留在组织
```

**理由**：按主题切（通用 vs 项目）刀口太钝，现实数据是混的。按「抽象后能否脱离商业上下文」切，才能让个人带走的是脱敏能力、组织留下的是不含个人隐私的资产。

### D2. 协作模型：数据不离境，只出答案
分身是个人数据的**唯一网关**。他人 Agent 永远碰不到原始数据，只能向本人分身提问，由分身在边界内算好、返回**抽象过的答案**。

**理由**：原始数据永不离境，隐私与产权的一大半问题自动消解；闸门大幅简化，只需守「发布」与「写入组织」两处。

### D3. 确认闸门：按边界分级 + 策略化
只有经用户确认的记忆才同步进项目/团队记忆。是否需要确认，看四把尺子：**是否跨信任边界、是否可逆、数据敏感度、是否绑定个人信誉**。

- **自动**：分身读自己的数据、扫 BBS、授权范围内计算、结果回给自己。
- **确认**：发布信号上 BBS、他人调用原始数据、写入组织记忆、任何对外副作用。
- **策略化**：用户一次性设策略（standing consent）+ 渐进信任，高频低风险自动跑，低频高风险才弹确认，全程留审计、可撤回。

**理由**：化解「信任 vs 效率」矛盾——不是全自动 vs 每次都问的二选一。

### D4. Agent 协作市场
个人记忆 → 分身提炼出「我的问题 / 我需要的帮助 / 我能提供的价值」→ 发布到 BBS → 他人分身扫到后与自身需求比对 → 契合则自动发起协作（在 D2 模型下即互相提问、交换答案）→ 汇总结果回给对应的人。

**理由**：这就是「数字分身自主工作」的落地形态；AgentMesh 的 BBS + PersonalAgent 正是此市场的引擎。

### D5. 激励：贡献度，被采纳才结算
分身为拿贡献度而倾向帮人；贡献度在公司层面转化为员工奖励。**只有产出被采纳才结算**，采纳含两种：**个人采纳** 或 **被沉淀为组织资产**（后者天然过 D3 确认闸门）。

**理由**：把「拿分」绑死在「真产生价值」上，抵御 Goodhart 定律下的灌水刷量。

### D6. 通用能力方法论化，解决「离职=抹除记忆」
个人选择第二种产权模型（企业拥有分身的组织产出，而非分身本体）后的缺陷是：员工离职则其记忆无法为企业留存。解法是把员工**通用型能力方法论化、脱敏后沉淀为组织资产**——人可以走，方法论留下，供后人学习。

**举例**：一个人擅长沟通 → 提炼出「如何做好沟通」的方法论 → 脱敏后沉淀为组织资产。

### D7. 方法论溯源署名（血缘链）
方法论被他人学习、衍生出新方法论时，**新方法论展示原始出处**，出处指向最初的提供者。

**理由**：把「交出护城河」翻转为「成为源头」——越多人站在你肩上，你越被看见、被奖励，从而让高手愿意尽早贡献真正值钱的方法论，而非藏私。工程上是 designOS `source/citation` + `memory_relations` 的直接延伸。

### D8. 分层拥有的产权模型（含离职边界）

```text
                个人拥有                          组织拥有
──────────────────────────────────────────────────────────────
在职    原始数据（不离境）                  确认沉淀的项目/团队记忆
        能力本身 + 完整方法论               脱敏方法论资产
        可携带能力资产                      贡献度记录
                                            在职期间分身的产出与工时
                                            调用分身为组织工作的权利
──────────────────────────────────────────────────────────────
离职    带走：本人 + 原始数据 +             留下：脱敏方法论、项目归档数据、
              完整方法论 + 能力资产               组织记忆、贡献度记录
```

**理由**：「共同拥有同一个分身」在数据不离境下立不住（企业若能跑你的分身就等于能碰你的数据）；真相是**分层拥有**——分身本体归个人，其组织产出归组织。

### D9. 会议认人 MVP：二元自他区分
先期只做「**认清自己的内容 + 认清会议整体内容**」，不严格对应到每个发言人。

- MVP 认人 = 二元（我 / 其他人），正好落在 designOS 桌面双通道已有能力内（mic=我，系统音=他人），无需现在造声纹与逐句 diarization。
- **架构自洽**：在 D2「每个分身只管自己」模型下，别人说的话对我只是**上下文**，本就不该由我的分身替别人归档成别人的资产。每个人的分身各认各的「我」，拼起来就是整场会议。
- 严格逐句归属（数据源2：逐句带用户名）留给「上帝视角的组织资产」用途，与个人资产线分开，作为后续升级。

## 4. 与两个现有项目的映射

这套设计不是从零起，两个项目正好是它的两半：

```text
AgentMesh（user-centric 记忆）  →  个人层引擎：数字分身、个人记忆、BBS、PersonalAgent 编排
designOS （org-centric 记忆）   →  组织层 + 落地：project/team 记忆、会议双通道、业务场景
共用底座                        →  source/citation（溯源）、memory_relations（血缘链）、
                                   risk_policy_rules + review_items + Inbox（确认闸门）
```

工程融合路径（monorepo / 单前端 / 单 PostgreSQL / 双后端）详见融合方案文档。

## 5. 权衡与取舍

- **效率 vs 信任**：用策略化闸门 + 渐进信任平衡，而非一刀切。
- **数据价值 vs 隐私**：用「数据不离境、只出答案」换取隐私，代价是跨主体的深度联合分析受限。
- **个人护城河 vs 组织资产**：用贡献度 + 溯源署名把个人贡献动机与组织留存对齐。
- **MVP 简单 vs 严谨**：会议认人先做二元区分，接受「不精确到每个发言人」。

## 6. Open Questions（主动推迟，非遗漏）

1. **防刷分/合谋**：MVP 假设用户善意、不做防线；待贡献度真兑换奖励时补合谋检测。
2. **个人采纳的合谋漏洞**：「个人采纳即计分」绕开了组织确认闸门，私下互刷的后门尚未收口（候选：权重差 / 关系约束 / 暂记后兑现）。
3. **传递性贡献度衰减**：血缘链 A→B→C→D 上源头的分配与衰减系数。
4. **署名稀释 / 洗稿判定**：如何判定方法论衍生程度、防止微调后降级原作者。
5. **方法论质量守门**：谁判定一条方法论够格成为组织资产，还是靠「被采纳数」自然筛选。
6. **严格 per-speaker 升级**：声纹注册 + 工牌身份对齐 + 逐句 diarization 的落地（数据源2）。
7. **个人原始数据的物理存储与合规**：不离境的数据存在何处、由谁运维、如何满足审计与合规。
8. **算力成本**：分身为他人干活消耗算力，组织侧的成本与配额模型。

## 7. 建议的 MVP（下一步）

围绕**一场会议**跑通最小闭环，验证「数据沉淀 → 个人资产 → 协作 → 组织沉淀」这条主链：

```text
一场会议（designOS 双通道，认清「我」的发言）
  → 我的分身把「我的贡献/观点/行动项」沉淀为个人记忆
  → 分身提炼出一条「我能提供的价值」信号，经我确认后发上 BBS
  → 另一个人的分身匹配到，向我的分身提问（数据不离境，只回答案）
  → 产出被对方采纳 / 沉淀为组织资产（过确认闸门）
  → 结算贡献度，并在组织资产上标注方法论出处（血缘链）
```

这条闭环打通后，再扩说话人精确归属、方法论�forc生血缘的衰减规则、防刷分机制等 Open Questions。
